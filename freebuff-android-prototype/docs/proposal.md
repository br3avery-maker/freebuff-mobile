# 提案:Freebuff 官方安卓手机 App(概念原型阶段)

> 面向 `CodebuffAI/freebuff` 开源仓库的产品扩展提案。
> 本文档对应同目录下的 HTML 高保真交互原型,用于信息架构与视觉方向评审。

## 背景与目标

Freebuff 目前以 CLI / 桌面端为主。移动端可补齐“随身编码助手”场景:
在路上读代码、接需求、由 Agent 规划并解释,回到电脑再执行。
本提案不替代桌面能力,而是服务“移动优先”的使用形态。

## 原型范围(已实现)

- **会话**:列表(最近/更早)、新建、重命名入口、清空/删除;消息含 Agent 状态卡、markdown、代码块与一键复制;演示流式输出与停止。
- **发起任务(底部「+」)**:三步向导 —— 代码仓库(不关联 / 手动地址 / Git 账号仓库)→ 模型(官方在上、自定义在下)→ 任务描述 → 发起。任务在对话页展示为带仓库/模型上下文芯片的用户消息,Agent 回复携带任务上下文;关闭向导保留草稿。
- **模型**:官方目录 + 用户自定义(OpenAI 兼容端点);当前模型可全局切换。
- **设置**:外观(深/浅/跟随系统)、模型(官方/自定义分组)、**集成(Git 账号 / 自定义模型)**、会话与数据、关于(含版本检查与更新演示:发现新版本 → 同意更新 → 进度 → 重启)。
- 深/浅双主题;文案集中于数据层,便于本地化;全部为演示仿真,不连真实服务。

## 信息架构建议(评审点)

```
一级(底部导航): 会话 | (新建) | 设置
二级: 对话页(模型/更多操作弹层)
设置内分组: 外观 → 模型 → 集成 → 会话与数据 → 关于
```

- “集成”承载账号与端点类授权:Git 账号(仓库读写授权)、自定义模型(自带 API)。
- 会话是否云端同步、登录体系、免费模式细则,建议与官方产品保持一致后另行设计稿。

## 后续计划

1. 原型评审(信息架构 / 交互 / 视觉走查)。
2. 输出交互走查清单与视觉规范(取色、字体、组件库)。
3. 与官方确认:以仓库新增产品目录方式推进原生安卓工程(技术选型、账号与模型接入)。
