# Freebuff 移动端助手:「建议操作 / 建议提示」功能配置

> 填表说明:模板里的 `[填写]` 按**本仓库这个 Agent** 填写。若指的是别的 Agent(如电商客服、日程助手),
> 只需替换 §1 的能力清单,§3/§4 的策略表可原样复用。
>
> 依据:NN/g《Designing Use-Case Prompt Suggestions》(首屏用例提示:突出高价值能力、可点可编辑、轻量可忽略)、
> Follow-up Chips 模式(Gemini/Perplexity/ChatGPT 的跟进卡:2–4 条、必须引用本轮内容、新回复即刷新、
> **多轮 Agent 运行中不要插建议**、不压制复制/重试等主操作),以及本仓库 `docs/agent-architecture.md` §4 里
> 后端既有工具 `suggest_followups`「卡片在 `end_turn` 之后渲染」的语义 —— 端侧实现与之一致。

## 1. Agent 基本信息

| 项 | 内容 |
|---|---|
| Agent 名称 | Freebuff 移动端助手(Freebuff Mobile,「随身编码 Agent」) |
| 核心功能 | 多轮工具的移动端任务 Agent:联网搜索 / 抓网页正文、读公开 GitHub 仓库(搜索·读文件·读 README)、精确计算、设备时间、记忆(核心记忆块 persona/user/project + 检索式记忆)、子代理调研;任务向导(选仓库 → 选模型 → 描述任务)、访客模式、8k~128k 上下文的会话压缩 |
| 目标用户 | 主:个人开发者(移动端碎片时间写脚本/查资料/读开源);副:会用 AI 做调研与排错的学生、产品与运营同学;中文优先 |
| 已知边界(建议里不要越界) | 无写文件/执行终端/搜索提交历史的能力;长任务受轮次上限(30)与上下文窗口约束;失败时一次重试后应换路 |

## 2. 建议操作(Suggested Actions)

### 2.1 初始建议(对话开始前,首屏 4~5 个 pill;访客模式同样展示)

| 功能场景 | 操作/提示语 | 用户点击后的期望行为 | 适用阶段 |
|---|---|---|---|
| 展示最典型能力:调研 | 查一下 Compose 1.8 有哪些新特性 | 短 pill 直接发出:触发 `web_search`(必要时 `web_fetch`),回答带来源链接;回合结束后换 2~4 个跟进卡 | 开始 |
| 展示工具闭环:精确计算 | 算一下 (12+8)*3.5,要过程 | 触发 `calculator`,给精确结果与算式,不心算 | 开始 |
| 展示实时能力 | 现在几点?离明天 9 点还有多久 | 触发 `current_time`,如实回答(不猜日期) | 开始 |
| 展示读仓库能力 | 读下 CodebuffAI/freebuff 的 README,给我 5 条要点 | 触发 `github_get_readme`;**先填入输入框**允许改 owner/repo 再发,回答 3~5 条要点 | 开始 |
| 展示记忆能力(第 5 个,可选) | 记住:我偏好回答尽量短 | 触发 `save_memory`(block=user,Add),回报「已记住」;并提示可在设置里查看/清空 | 开始 |

### 2.2 后续建议(每次响应后,2~4 个 chip;由模型提议 + 端侧护栏)

| 功能场景(按回合结局) | 操作/提示语 | 用户点击后的期望行为 | 适用阶段 |
|---|---|---|---|
| 正常答完、本轮有可深化点 | 模型生成,如「把第 2 条展开成对照表」 | 生成时必须引用本轮内容;与最近 3 条建议去重;点击即作为下一轮用户消息;**新回复替换整组建议** | 回复后 |
| 本轮用了工具 / 拿到新资料 | 把它整理成 5 条要点 / 换成中文重写 | 直接基于已有上下文回答,**不重复调用工具**;端侧可确定性追加「整理成要点」 | 回复后 |
| 任务未完成(端侧续跑提醒过 / 触到轮次上限) | 继续 / 按这个思路做下一步 | 延续同一任务,不重做已完成部分;达到 30 轮上限时给「接着做」而不是新任务 | 回复后 |
| 缺信息 / 需要用户决定 | 用国内可访问的来源重查 / 换成 8k 上下文的模型 | 回答里提了问题 → 建议给**可点选的具体答案**,点击即作答继续(不再追问一遍) | 回复后 |
| 失败(工具报错、401/403/429、断流) | 换个参数重试 / 换一个模型 / 先跳过这一步 | 只提供**一次**重试 + 换路入口;不诱导重复同一调用(对应错误信封的「连错两次就换路」) | 回复后 |
| 涉及记忆写入 | 记住这个偏好 / 不用记 | 走 §3 行为策略:确认卡或直接写入;「不用记」后本会话不再提 | 回复后 |
| 闲聊/短问候、无实质后续 | 不出建议(留白) | 宁可空着也不塞卡片;连续 2 轮无实质后续则停止生成 | 回复后 |
| 正在多轮工具循环中(`streaming=true`) | —— | **不渲染任何建议**(会打断进行中的计划);等回合收尾再出 | 运行中 |

## 3. 建议提示语(Suggested Prompts,首屏 8~10 条)

| 覆盖能力 | 提示语 | 用户点击后的期望行为 | 适用阶段 |
|---|---|---|---|
| 事实核查(搜索) | 帮我核实:Android 15 是否强制 edge-to-edge? | `web_search` → 结论 + 来源链接 + 一句不确定性说明 | 开始 |
| 读公开仓库 | CodebuffAI/freebuff 的 README 说了什么?适合谁用 | `github_get_readme` → 3~5 条要点,超出能力(如提交历史)如实说明 | 开始 |
| 代码生成 | 用 Kotlin 写个带重试的下载函数,逐行解释 | 直接生成代码块 + 逐行说明;不调用工具 | 开始 |
| 排错诊断 | Gradle 报 Unsupported class file major version,可能原因? | 给候选原因清单 + 各自验证方式,末尾问一个关键信息 | 开始 |
| 精确计算 | 1.5 万美金的 7% 税是多少?再除以 3 个人 | `calculator` 两次调用 → 精确数值 + 算式 | 开始 |
| 实时信息 | 现在时间?顺便算下今天还剩多少小时 | `current_time` → 如实数字,不猜 | 开始 |
| 记住偏好 | 记住:我在做 Android 项目,回答尽量短 | `save_memory`(user/project)→ 回报已记住 | 开始 |
| 回忆偏好 | 我上次让你记住过什么? | `memory_recall`(user_id=local)→ 列出条目并标注来源时间 | 回复后 |
| 调研汇编 | 对比 Room 与 SQLDelight 在 KMP 下的取舍,给结论表 | `web_search`(+ 可选子代理)→ 结论表 + 取舍建议 | 开始 |
| 推进旧任务 | 继续上次没做完的那件事 | `memory_recall`(短期待办)→ 复述进度再继续,不从头重做 | 回复后 |

## 4. 行为策略选项(Add / Replace / Suggest / Do Nothing)

映射到现有实现:`save_memory(block, content, replace)` —— `replace=true` = **Replace**,`replace=false` = **Add**;
**Suggest** 需新增「建议写入」确认卡(采纳后才写);**Do Nothing** 是默认(没有明确信号就不调用工具)。
另建议补 **Delete**(「忘掉 X」)与设置页的「查看/清空记忆」,四个选项不足以覆盖用户真实诉求。

| 字段 / 记忆类型 | 默认策略 | 何时触发 | 冲突时 | 用户点击/写入后的期望行为 | 适用阶段 |
|---|---|---|---|---|---|
| `user` 偏好与习惯(long_term) | **Add**(追加不覆盖) | 用户以第一人称明确陈述偏好(「我喜欢…」「以后都…」) | 与新陈述矛盾 → **Suggest**(带 diff:「把「短」换成「极简」?」) | 追加到 user 块;单块 600 字上限,超限先精炼;回复一句「已记住:…」 | 回复后 |
| 关键事实(long_term,项目名/技术栈/角色) | **Add + 去重** | 用户明确给出事实 | 同键不同值 → **Suggest** | 同内容重复出现只刷新 `updatedAt` 与 `hits`,不新增重复条目 | 回复后 |
| `project` 任务焦点与进展 | **Replace** | 任务开始、阶段完成、用户说「记录进度」 | 无 | 整块替换为当前焦点(旧焦点压成一句历史);替换前把旧内容摘要保留在回复里 | 回复后 |
| 短期任务进度(short_term) | **Replace**(同任务内)/ **Do Nothing**(跨天陈旧) | 有明确阶段结论 | 与旧进度矛盾 → **Replace** | 覆盖同任务旧进度,不无限追加;跨天未续的任务不自动写入 | 回复后 |
| `persona`(助手身份) | **Replace**(仅助手自维护) | 初始化 / 设置页修改 | 无 | 用户对话路径不得改 persona;避免人格漂移 | 任意 |
| 模型推断出的信息(用户未明说) | **Suggest** | 高价值且非敏感(如从中推断用户在做的项目) | —— | 只出「建议记住:… ✓/✗」卡;不静默写入 | 回复后 |
| 敏感信息(密钥/token、身份证、住址电话、健康/宗教/政治) | **Do Nothing** | 任何情况 | —— | 永不写入、不在回复中复述;必要时明确告知「这类信息我不会保存」 | 任意 |
| 用户说「别记 / 忘掉 X」 | **Do Nothing + Delete** | 用户明确表达 | —— | 不写入;并删除匹配条目,回报「已删除 N 条」 | 回复后 |
| 写入失败(库异常 / 超限) | **Do Nothing** | 写入抛错 | —— | 静默失败、不回滚对话;**不在回复里声称「已记住」** | 回复后 |

**决策顺序(端侧确定性规则,优先于模型自述)**
1. 敏感? → **Do Nothing**(最高优先级,压过一切)
2. 用户明说? 否 → 高价值且非敏感? **Suggest** : **Do Nothing**
3. 与现有值冲突? 整块字段(project/persona)→ **Replace**;条目型(user 偏好、事实)→ **Suggest**(带 diff)
4. 其余 → **Add**

## 5. 提示词与护栏(回复后建议怎么生成)

**生成方式**:回合收尾(`op finish`)后,复用本轮模型做一次**非流式小请求**生成建议;
失败则退回端侧固定规则(完成/失败/未完成三类各 2 条),再不行就不显示 —— 不给建议好过给错建议。

```
你是移动端助手的「下一步建议」生成器。基于本轮问答,输出 2~4 条用户下一句最可能说的话。
1) 每条 ≤ 12 个汉字,动词或疑问句开头,用用户口吻(「把它整理成表」),不要用助手口吻;
2) 必须引用本轮的具体对象/结论;禁止「继续」「还有吗」这类空话(除非本轮明确未完成);
3) 一条一个动作、可独立执行(点开即发,不需要补充信息);
4) 不重复最近 3 条已给过的建议;若本轮失败,建议必须是「可换的参数/工具/模型」;
5) 不生成删除、支付、对外发送等有副作用的动作;
6) 没有实质后续就输出空数组,不要硬凑。
只输出 JSON:{"suggest":["…","…"]}
```

**端侧确定性护栏(模型输出必须过一遍)**
长度 ≤ 16 字 / 数量 2~4 / 与最近 3 条做模糊去重 / 黑名单(重复同一失败调用、删除分享类) /
去重后不足 2 条则整组不显示 / 仅在 `streaming=false` 且回合已收尾时渲染 /
长句点击后**先填入输入框可编辑**,短句直接发送 / 新回复替换整组旧建议。

**埋点与指标**:首屏建议点击率、建议采纳率(点击/展示)、建议→首任务完成率、
平均轮次、去重丢弃率、失败后「换路」类建议点击率(反映错误信封是否真的帮上忙)。

## 6. 落地位置(本仓库)

| 能力 | 落点 |
|---|---|
| 首屏 pill | `feature:chat` 的聊天空态区(输入框上方);文案与图标进 `core:model` 常量,便于本地化 |
| 回复后 chip | 新增本地工具 `suggest_followups`(与后端同名同语义),端侧 codec + §5 护栏;收尾钩子在 `ChatViewModel` 现有 `finishAgent` 之后 |
| 记忆策略 | `save_memory` 的 `replace` 映射 Add/Replace;Suggest 复用 `_pendingConfirmation` 卡片;Delete 需新增记忆管理入口 |
| 安全 | 敏感信息 Do Nothing 属硬规则,写在工具执行入口(与 `ToolPermissions` 同级),不依赖提示词自觉 |
